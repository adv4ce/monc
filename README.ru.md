# Monc 💰

Движок двойной записи на Elixir, Ecto и PostgreSQL.

Деньги не появляются и не исчезают: транзакция - это набор проводок, сумма которых равна нулю. Баланс нигде не хранится, он считается как сумма проводок по счёту.

## 📐 Модель

| Таблица | Что это |
|---|---|
| `monc_accounts` | Счёт: валюта и флаг `allow_negative` |
| `monc_transactions` | Атомарная группа проводок |
| `monc_postings` | Изменение баланса одного счёта одной транзакцией |

Проводки только добавляются, ничего не обновляется и не удаляется.

## ✅ Гарантии

Транзакция записывается, только если выполнены все четыре условия:

- сумма проводок равна нулю
- все счета в одной валюте
- счёт с `allow_negative: false` не уходит в минус
- либо записаны все проводки, либо ни одной

## 🔒 Конкурентность

Порядок записи:

1. `SELECT ... FOR UPDATE` по всем счетам транзакции, `ORDER BY id`
2. вставка транзакции и проводок
3. пересчёт балансов и отказ, если кто-то ушёл в минус

Блокировка идёт **до** вставки. Иначе `INSERT` проводки сам берёт на счёте слабый `FOR KEY SHARE`, две параллельные транзакции спокойно берут его одновременно - и обе навсегда виснут, пытаясь поднять его до `FOR UPDATE`. `ORDER BY id` закрывает вторую, обычную разновидность дедлока: когда транзакции ходят по пересекающимся счетам в разном порядке.

Проверка баланса идёт после вставки и внутри той же транзакции, поэтому видит свои же проводки и читает итоговый баланс напрямую.

## 🚀 Использование

```elixir
{:ok, treasury} = Monc.Accounts.create_account(%{currency: "USD", allow_negative: true})
{:ok, alice}    = Monc.Accounts.create_account(%{currency: "USD"})

{:ok, _} =
  Monc.Ledger.record_transaction(%{
    description: "пополнение",
    postings: [
      %{account_id: treasury.id, amount: -1000},
      %{account_id: alice.id, amount: 1000}
    ]
  })

Monc.Ledger.get_balance(alice.id)
#=> 1000
```

Суммы - целые в минорных единицах (копейки, центы), не float.

Ошибки:

```elixir
{:error, :unbalanced_transaction}
{:error, :restricted_ids, :mixed_currencies, _}
{:error, :check_balances, :insufficient_funds, _}
```

## 🧪 Запуск

Нужен Elixir 1.19+ и Postgres. Скопировать `.env.example` в `.env` и заполнить.

```bash
mix deps.get
mix ecto.create
mix ecto.migrate
mix test
```

`test/concurrency_test.exs` - нагрузочный: тысяча счетов, сто тысяч случайных переводов между ними в параллель, проверка что ни один счёт не ушёл в минус.

```
%{ok: 98572, errors: 0, insufficient_funds: 1428}
Finished in 33.6 seconds
```

Отказы - это законная нехватка средств. `errors: 0` значит, что ни один воркер не упал: так проявился бы дедлок.

## ⚠️ Чего пока нет

- **Идемпотентности.** Клиент, повторивший запрос после обрыва сети, проведёт перевод дважды. Нужен `idempotency_key` с уникальным индексом.
- **Проверенной встраиваемости.** `Repo.Proxy` задуман, чтобы хост подсовывал свой репозиторий, но этот путь ни разу не гонялся. Мешают две вещи: `Monc.Application` безусловно поднимает свой `Repo`, а миграции не отдаются наружу.
- **Слоя доставки.** Это библиотека, HTTP и UI поверх неё нет.
- **Дешёвого баланса.** `SUM` по всей истории счёта дорожает с её ростом - со временем понадобятся снапшоты.
